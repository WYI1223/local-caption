# 识别与降噪首轮受控实验

2026-09-16。先发布保存修复 `3906063`，本轮实验不改变发布版默认识别参数或开启降噪。使用相同 Nemotron 0.6B Q8 CPU 模型，对每一段音频固定解码样本后比较；没有人工逐词真值，不报告 WER 或“准确率提升百分比”。私人录音、识别结果和听辨片段只在被忽略的 diagnostics 下保留。

## 方法与边界

入口：`scripts/compare_asr_preprocessing.py --clear <清晰录音> --noisy <模糊录音> --clear-start <秒> --noisy-start <秒>`。原文件只读，输出单声道 16 kHz PCM16。该脚本目前是 Windows 本地实验工具，需要已安装 ffmpeg 与模型，尚未作为稳定功能发布。

每段比较原音实时 R=1、原音实时 R=13、原音离线、现有保守响度处理后实时 R=1、80 Hz 高通加 FFT 降噪后实时 R=1。FFT 参数为 `afftdn=nr=6:nf=-40:tn=1`。附加消融将高通和降噪拆开，并尝试较轻的 `nr=3:nf=-55:tn=0`。

依据：[NeMo 配置说明](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/v0.1.0/docs/asr/configuration.md) 将右侧上下文作为流式执行策略；[FFmpeg afftdn](https://ffmpeg.org/ffmpeg-filters.html#afftdn) 定义噪声地板、衰减强度和噪声跟踪参数。本轮测试的具体参数是工程假设，不是厂商推荐的课堂预设。

清晰片段请求截取 25 秒，实际 PCM 为 22.0439375 秒；将 seek 从输入移到输出端后长度仍相同。M4A 容器时间与解码采样时长不能混用，尚未确定具体封装原因。模糊有效语音片段实际 24.939 秒。所有同段变体使用同一 PCM 样本序列，滤波后样本数一致。此前一分钟系统回放只采集到 57 秒，不能单独据此认定音频归档丢帧，也不能在未核对时间戳前将差值完全归因于源文件。

首个模糊候选主要没有可识别语音，各方案只有空结果或短句；不把它当有效识别质量样本。随后向后选取含连续讲话的片段。

| 高通＋FFT 降噪，R=1 | 10.89 s | 输出明显缩短，原本输出的句子消失，存在弱语音损伤风险 |

墙钟耗时不是实时字幕延迟，且只有每项一次运行，不能作为稳定性能提升。原生日志显示 R=13 的推理步长为 1120 ms，R=1 为 160 ms；更大上下文可能提高吞吐，但要等待更多音频，不应因文件转写更快就默认切换。

清晰样本当前实时配置已经保留核心术语；这些预处理没有显示出足够证据支持默认开启。模糊有效样本原始 RMS 约 −25.49 dBFS；80 Hz 以下频带能量仅约 0.18%（25 ms Hann 窗能量统计），不能把整段问题归结为低频轰鸣，也不能从总 RMS 推算真实语音 SNR。

## 碰撞候选与下一步

从模糊录音的一段五分钟解码音频中，以 10 ms RMS 对前 0.5 秒中位数的突增、随后短期回落及峰值筛出候选，截出三个六秒原音片段供听辨。它们是声学异常候选，未标注为碰撞；讲话爆破音也可能满足条件。旧限幅器在所测模糊连续讲话样本触发 0 次，降低阈值前必须验证不会削弱语音。

当前决定：不启用本轮 FFT 降噪方案，不改默认右侧上下文。先确认碰撞时间点，建立“碰撞可衰减、讲话不可误伤”的小型人工核对集，再评估定向瞬态抑制。低频过滤和更大上下文保留为候选。音频归档必须始终在任何增强之前，供重新识别与审计。


## 第二轮：其他算法同段比较

同日新增 `scripts/compare_denoise_methods.py`，用 `--input <16k单声道PCM16 WAV>` 可重复传入多段，固定原始样本、真实 NeMo CLI CPU 流式 R=1。比较非局部均值（`anlmdn=s=0.001:p=0.002:r=0.006`）、轻度小波（`afwtdn=sigma=0.003:percent=40:samples=512:levels=6`）、去点击（`adeclick=t=4:w=30`）；另以 `--rnn-model <本地模型> --methods rnn_half rnn_full` 比较神经网络混合强度 0.5 / 1。

算法参数定义参见 [FFmpeg 文档](https://ffmpeg.org/ffmpeg-filters.html)。神经网络使用 [arnndn-models](https://github.com/richardpl/arnndn-models/tree/0fda24c46d78f0207d820bb970fbe85c1971b39c) 的 cb.rnnn，SHA-256 为 f1357c4e5be9dee8467bead486dfced2d75b640c26ad0b594fa7f102322371d9，只下载到被忽略目录供本机实验，不加入安装资产或源码包。这不是对所有 RNNoise 模型的结论。

共完成 18 次真实识别：清晰 22.044 秒、模糊 24.939 秒、疑似瞬态 6 秒，各原音加五个处理变体。全部成功退出，输出 WAV 样本数与各自原音一致。

| 方法 | 模糊片段预处理耗时 | 模糊片段输出词数（非准确率） | 本轮判断 |
| --- | ---: | ---: | --- |
| 原音 | — | 47 | 错词仍多，作为基线 |
| 非局部均值 | 0.285 s | 31 | 无可靠改善，波形延后 8 ms 是额外变量 |
| 小波 | 0.158 s | 42 | 核心错词仍在；不支持默认开启 |
| 去点击 | 0.183 s | 46 | 对疑似瞬态峰值基本无影响 |
| 神经网络半强度 | 0.362 s | 20 | 输出明显缩短，弱语音漏识别风险 |
| 神经网络全强度 | 0.382 s | 8 | 不适合当前模糊片段 |

神经网络全强度将模糊片段 RMS 降到原来的约 8.7%，这不是 SNR 提升；在疑似瞬态片段把原音尚能识别的三个词变为空文本。清晰片段原音与半强度各 60 词，全强度 58 词并出现点位字母变化，故不能以清晰样本上的相近输出推断远距离讲话适用。轻度传统方法在疑似瞬态片段的峰值几乎不变，未证明拍桌抑制有效。未经人工听辨标注，不把疑似瞬态自动认作碰撞。

性能范围：25 秒样本的预处理耗时为音频时长约 0.64%–1.53%，仅为单次文件处理（含进程启动），不是实时回调延迟或长期无积压证明。识别单次耗时约 11.7–13.4 秒（含模型加载）；本轮未开启翻译、系统声音回放或长时采集，因此没有整应用积压结论。

可复用经验：anlmdn 本轮互相关测得输出延后 128 个样本（8 ms）；未对齐波形差值不可解释为降噪量。arnndn 在 48 kHz 处理后尾部补齐帧，首次清晰样本输出多 97 个 16 kHz 样本，严格检查捕获后增加 `atrim=end_sample` 去除尾部补齐，再验证样本数；不通过任意填零掩盖缺失。采样数相同本身仍不证明滤波无延迟或无语音损伤。

原始 JSON、模型来源摘要和可试听对比页保存在本机忽略目录 `diagnostics/denoise-methods-20260916-201038` 与 `diagnostics/denoise-methods-20260916-201302`。没有人工逐词真值，不报告 WER；本轮保留应用现有默认设置。后续优先确认碰撞标注，并把近场降噪与远场弱语音增强分开评估。


## 第三轮：固定背景轮廓与有限谱减

入口 `scripts/compare_noise_profile.py --background <邻近背景候选 WAV> --input <固定语音 WAV>`，可重复传入 input。背景取同一模糊录音此前从容器 1800 秒位置解码的片段；按一秒 RMS 排序，选出不重叠的两个候选（解码片段内第 5 秒和第 3 秒，约 −44.77 / −44.75 dBFS）。仅凭低能量不能证明没有讲话，轮廓状态明确为未人工确认，不能发布成自动校准成功。

本轮为独立 NumPy 原型，不是前两轮 afftdn 的另一组参数：16 kHz、512 点 Hann 窗、128 点步长，从候选内部帧的功率谱中位数学习固定轮廓，按 `sqrt(max(0, 1 - noise_power / signal_power))` 得到增益；每频段衰减上限分别为 2 / 4 dB，再做频域与时间平滑、重叠相加重建。不更新轮廓、不使用未来课堂内容估计噪声。离线实现仍有窗口前瞻，不等同于已实现低延迟实时后端。该经验方案的参数不是经验证的通用预设。FFmpeg 另有 [sample_noise 学习接口](https://ffmpeg.org/ffmpeg-filters.html#afftdn)，本轮没有混用其自动噪声追踪。

完成两个轮廓 × 两个强度加原音，共两段、10 次实际 NeMo CPU R=1 转写。24.939 秒模糊语音原音 47 词，四种处理分别 41 / 41 / 43 / 42 词；术语错误仍存在，未证实准确率改善。讲话片段 RMS 保留约 98.5%–98.9%，比此前神经网络全强度的严重整体压制温和；音量保留不是语音无损或准确率指标。疑似瞬态的六秒片段五种输入均输出相同三个词，不能据此证明碰撞抑制有效。

跨候选核对：用候选一的轮廓处理未用于建模的候选二，2 / 4 dB 上限下 RMS 下降约 1.69 / 2.79 dB。这仅是背景候选能量下降，不是已知纯噪声下的 SNR 改善。连续讲话 24.939 秒的纯 NumPy 预处理耗时 0.080–0.104 秒；不含实时采集、翻译或排队，未做实时积压验收。

验证：每个真实输入用零轮廓重建，长度保持、最大误差小于 1e-10；合成正弦加噪声用 0 / 2 / 4 dB 验证重建与增益下限，0 dB 最大误差约 9.7e-17；全部输出样本数不变、数值有限。每频段增益上限不代表每个时域采样点都不变；需要同时听原音、处理后及被减去的差分，排查弱语音泄漏。

私人证据与试听页：`diagnostics/noise-profile-20260916-202246/{results.json,compare.html}`，包含两个轮廓候选及原音减处理后的差分音频（未放大）。当前结论：固定轮廓、限制衰减值得保留为实验路线，但尚无证据支持默认开启。下一步需要人工确认纯背景候选、语音真值和不同时间段上的有效性，避免把安静讲话当噪声学进去。应用设置和原始录音未改动。


## 106 分钟原录音的代表性复测

用户反馈上一轮片段相对清楚，并说明整堂课教授音量偏小、噪声较多。因此在同一原文件重新固定选择容器 10 / 50 / 65 分钟处各请求 25 秒，实际每段解码 24.939 秒；每段用前 30 秒独立选择两份背景候选，不挑识别效果好的区间。上一轮模糊片段也来自这份 106:51.656 原录音的约 30:30 处，不能把“同一文件”混同于“已覆盖整堂课”。源文件元数据、每段位置和实际样本数写入本机 `diagnostics/noisy106-multisegment-20260916/source.json`。

媒体边界发现：请求容器 85 分钟处得空 PCM；ffprobe 在 5070 秒处 seek 返回 PTS 4413.826063、duration 1715.754604 的异常长时包。仅记录现象，不据此推断内容永久丢失或用户录制错误。容器总时长不能代替解码帧数；实验入口现已提前拒绝零样本音频，避免把提取失败混记成降噪后空识别。改用 65 分钟处的有效音频，原文件未修改。

复测完成：三个时间点各原音＋两候选×两强度，共 15 次真实模型识别成功。10 分钟处词数为 19 / 16 / 18 / 19 / 18，50 分钟处 28 / 21 / 21 / 21 / 21，65 分钟处 64 / 62 / 60 / 62 / 62（顺序：原音、候选一 2/4 dB、候选二 2/4 dB）。词数不是准确率；第一段部分词组更符合上下文但没有真值确认，第二段输出缩短，第三段出现原音词组处理后变差。因此没有跨时间段一致的识别收益，不改默认配置。私有试听页 `diagnostics/noisy106-multisegment-20260916/compare.html` 明确标注完整源文件名、容器截取位置、实际样本时长，并提供每段原音、处理结果、背景候选与未放大的差分。下一步应针对远场弱语音及混响评估，而不能仅凭降噪后的主观安静程度推断识别改善。


## 远处小声讲话：增益与频段调整实验

入口 `scripts/compare_farfield_gain.py`，继续固定同一 106 分钟录音的 10 / 50 / 65 分钟处三段 PCM，不重新选片段。每段比较原音、仅增益、同 RMS 的频段调整、频段调整加增益，真实 Nemotron Q8 CPU R=1 转写。这里是增益/EQ 消融，不是声源分离、去混响，也不声称恢复录音里不存在的细节。

频段候选为 80 Hz 高通、250 Hz −2 dB（Q 0.7）、2 kHz +3 dB（Q 0.7），参数是本次实验假设；[FFmpeg equalizer 定义](https://ffmpeg.org/ffmpeg-filters.html#equalizer)。先以 float64 输出滤波结果，再匹配原音 RMS，最后按需要加最多 2 倍（约 +6 dB）的线性增益。按整段峰值保留 0.95 余量，避免用削波换音量；这一整段预知峰值的保护属于离线方法，不能直接作为实时算法实现。每个变体同时生成同 RMS 试听副本，实际 ASR 始终使用未匹配的目标变体，避免把试听控制和送模音频混用。

验证边界：真实输出核对样本数、有限值、PCM16 无饱和样本；低/中/高三个合成峰值检查增益不超过 2 倍且峰值不超过 0.95。单纯线性增益不改善原始信噪比，不能以更响作为识别增强成立的证据；目前无人工逐词真值，不报告 WER。原音和应用配置未修改。


增益实验中发现原音峰值约为 0.5005 / 0.99997 / 0.9456（10 / 50 / 65 分钟），50 分钟处原始 PCM 已有 5 个饱和样本。验证必须区分输入既有饱和与处理新增削波，不能把原音基线判为算法失败。整段峰值限制下，纯增益实际只有约 +5.57 / −0.45 / +0.04 dB，后两段没有统一放大的空间。

因此补入独立的缓慢音量调整：10 ms 缓冲内检查峰值，上升时间常数 1.5 秒、下降 0.1 秒，目标 RMS 0.08、增益最高 3 倍，低于 RMS 0.004 不提升目标增益，每块峰值限制为 0.95。它是响度调整，不是语音检测或噪声分离；无语音的噪声也可能被放大，且块峰值保护尚未验证听感伪影。合成低声正弦加单次脉冲检查显示低声部分约 2.23 倍、峰值不超过 0.95，零输入保持零、样本数不变；不能把合成信号测试当真实讲话质量验收。

原生 CLI 拒绝覆盖已有 TXT，实验中断重试需处理该工具生成且尚未写入成功结果的 TXT，不能把文件存在错误记作识别质量失败。本轮脚本增加 resume 跳过已记录结果，仅替换该次未完成实验的生成 TXT。


本轮最终完成 3 段 × 5 变体，共 15 次有效真实识别。全部增强输出没有新增 PCM16 饱和样本，样本数相同。原音 / 纯增益 / 同 RMS EQ / EQ＋增益 / 动态音量调整的词数分别为：10 分钟 19 / 20 / 22 / 19 / 16；50 分钟 28 / 28 / 27 / 27 / 29；65 分钟 64 / 64 / 64 / 64 / 63。仅用于记录输出范围，不是准确率。第一段纯增益使末尾出现更合理的 Gaussian 词组，但仍未人工确认；第二段术语及公式错误未解决，动态调整还出现新的不合理词组；第三段未见可靠改善。不支持默认开启任何候选。

动态调整的整体 RMS 变化约为 +1.56 / +1.34 / −1.87 dB，说明同一目标响度会对各段产生不同方向的变化，不能笼统说整堂课都被放大。总 RMS 无法区分讲话和噪声，识别结果也不能证明剩余问题必然由混响引起。此次不将结果包装为“远场语音恢复成功”。听辨页 `diagnostics/farfield-gain-20260916-203625/compare.html` 提供实际送模音频与同 RMS 试听副本；原始 JSON 保留参数、输入摘要、输出峰值及识别结果。没有采集/翻译实时队列测试，处理方案仍只在离线实验脚本中。

后续选型：已完成 [远场增强论文与开源方案研究](farfield-paper-evidence.md)。推荐首轮 GTCRN / DPDFNet2 与对齐原音回混，先建立小型人工参考、区分开发与验证片段；不再以输出词数或听感变安静单独决定默认方案。研究未替代模型实测或实时队列验收。


## GTCRN / DPDFNet2 / 单通道 WPE 实测方法

入口 `scripts/compare_neural_wpe.py`。隔离环境位于本机忽略的 diagnostics 内，未改变应用 venv：sherpa-onnx 1.13.8、nara-wpe 0.0.11、NumPy 2.4.6、SciPy 1.17.1。两个 ONNX 均取自 [sherpa 官方模型发行](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speech-enhancement-models)，DPDFNet2 SHA-256 与 GitHub release digest 相符；GTCRN 发行未提供 digest，本机记录下载后摘要供复现，不能称为独立摘要验证。

继续固定 10 / 50 / 65 分钟的原始 PCM。增强输入为相邻背景的最后 5 秒、目标 24.939 秒、1 秒零尾部；前导帮助模型建立状态，零尾部供滤波器收尾，目标段不填零或截短。两个神经网络使用官方离线 API、单 CPU 线程，DPDFNet 关闭内置衰减限制，再显式测试原音与增强各 50% 的波形回混。WPE 使用单通道、512 点窗、128 hop、taps=10、delay=3、3 次迭代、整段统计，属于离线去混响对照。

依据官方 [GTCRN 实现](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-speech-denoiser-gtcrn-impl.h) 和 [DPDFNet 实现](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-speech-denoiser-dpdfnet-impl.h) 核对状态与延迟补偿；WPE 参考 [作者示例](https://github.com/fgnt/nara_wpe/blob/master/examples/WPE_Numpy_offline.ipynb)。互相关只在 ±100 ms 范围估计整体延迟，不能用来证明所有频率的相位或每个词无失真。人工构造的 0/128/640 样本延迟检查通过。WPE 的 STFT/ISTFT 在原样回环时误差小于 1e-5，目标长度及有限值检查通过。

每段原音、GTCRN、GTCRN 50% 回混、DPDFNet2、DPDFNet2 50% 回混、WPE 分别送入相同原生 NeMo CLI。增强峰值必要时整体缩小到 0.98，保存缩放系数并检查无新增饱和；原音既有饱和保留。音量匹配副本仅作试听，有峰值保护，必要时不能达到完全相同 RMS。没有新增人工逐词参考，不用输出词数计算准确率。本轮文件实验不代表在线 API、麦克风或全应用长期队列验收。

## GTCRN 后轻度动态增益补测

用户试听反馈 GTCRN 明显降低噪声，但人声仍模糊；这是主观听感反馈，不能等同于 ASR 准确率提高。入口 `scripts/compare_gtcrn_level.py` 复用上述三个时间点保存的 GTCRN / 50% 原音回混 WAV，并记录输入 SHA-256。只重跑六份增益后音频的实际 Nemotron CPU R=1 识别，基线文本复用同一 WAV 的上一轮输出。

参数：10 ms 帧、目标 RMS 0.063、最高 2 倍增益、上升时间常数 1.5 秒、下降 0.2 秒、帧峰值上限 0.95；RMS 低于 0.004 的帧不放大。能量门限不是语音检测，不能保证只增强人声。合成静音、弱正弦和脉冲检查通过；六份实际输出长度不变、数值有限、无 PCM16 饱和，全部 CLI 成功退出。试听页 18 个音频链接逐一核对存在且均为 399,024 样本 / 16 kHz。这是离线文件路径验证，未验证应用实时队列。

整体 RMS 增量为 +0.44 至 +1.10 dB。完整 GTCRN 后加增益，三个片段输出词数由 18/17/61 变为 8/15/60，第一段丢掉基线中的部分均值、方差词组；50% 回混后加增益由 23/31/61 变为 29/30/61，末段文字完全相同。第一段回混版本出现更通顺的新词组，但未经人工真值确认，不能算正确补回。公式片段仍有明显不合理文字，不支持默认启用增益。词数不是准确率，当前没有 WER。

证据与配对试听：`diagnostics/gtcrn-level-20260916-211550/{results.json,compare.html}`。可复用结论：降噪听感、响度和识别质量应分别判断；即使温和增益且无削波，也可能改变识别输出，不能仅凭音量更响部署到识别入口。保留 GTCRN 作为降噪候选，增益继续作为独立实验选项，应用默认设置未改变。


## 系统回环长测：弱语音选择性增益

入口 `scripts/system_weak_voice_ab.py --play <PCM16 WAV>`，使用 `diagnostics/enhancement-env/Scripts/python.exe`。这是隔离实验入口，不替换应用的旧“课堂增强”开关。新增隔离依赖 PyAudioWPatch 0.2.12.8，Silero VAD 模型来自 [sherpa 官方发行](https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/silero_vad.onnx)，下载摘要记录在每次 results.json 中；API 依据本机 sherpa-onnx 1.13.8 的公开绑定核对。

默认 WASAPI 回环只采集一次，分成原版和在线 GTCRN＋弱语音增益两路，避免两个设备采集时钟不同。设备 48 kHz 音频先经过两路共同的有状态 FIR 抗混叠降采样至 16 kHz；这里“原版”指没有降噪和增益，仍包含共同采样率转换。GTCRN 使用 OnlineSpeechDenoiser 连续状态和 flush，不以分块反复重建离线模型代替在线模型。保存原始 48 kHz 设备音频、16 kHz 基线、GTCRN 中间结果及最终增强音频。模型 flush 后要求三路 16 kHz 样本数完全一致，不通过截断补齐来隐藏长度问题。

Silero VAD 在 GTCRN 输出上运行，512 样本帧，阈值 0.5、最短语音 64 ms、静音保持 96 ms。只在检测为语音、RMS 0.0032–0.05 且非稀疏大峰值时，向目标 RMS 0.063 缓慢增加增益，最高 2 倍，上升/下降时间常数 1.5/0.2 秒。正常/非语音帧增益为 1；峰值保护只限制额外增益，不削波。VAD 具有检测滞后，也可能漏掉最弱讲话；此方案不承诺恢复模糊细节或精确区分所有碰撞声。帧间切换听感仍需试听。

短测 `diagnostics/system-weak-ab-20260916-213245` 通过真实播放→WASAPI→在线增强→保存→两路实际 C ABI 识别，采集 14 秒，队列无积压；438 帧中语音判断 330 帧、提升 146 帧、最高平均帧增益 1.327 倍。两路词数 29/11，不据此判断准确率。另用真实 VAD 静音检查和受控 VAD 门控分别验证弱语音提升、正常/非语音逐样本不变、孤立脉冲不提升、长度和有限值。受控门控检查不验证真实 VAD 分类准确率。

内存边界：长测启动时可用物理内存约 1 GiB、可用提交内存约 7 GiB；依据此前双实例内存失败，选择同时采集并实时增强、结束后用单一模型依次识别两路。前端队列数据不能当双路实时 ASR/翻译积压验收；离线解码耗时也不是字幕延迟。完整事件写 JSONL，并通过现有 TranscriptHistory 累积 final 与 partial，避免只保留最后一次识别文本。正式十分钟结果见下。
